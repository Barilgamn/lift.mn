# LIFT.MN

Монголын лифт, эскалаторын нэгдсэн цахим портал. DELTA LIFT брэндийн танилцуулга,
засвар үйлчилгээний захиалга, сэлбэг хэрэгслийн цахим худалдааг нэг дор нэгтгэсэн.

## Урьдчилсан шаардлага

**Node.js 20 буюу түүнээс дээш хувилбар.** Өөр юу ч суулгах шаардлагагүй.

Суусан эсэхээ шалгах:

```bash
node -v
```

Хэрэв `command not found` гарвал [nodejs.org](https://nodejs.org) дээрээс **LTS** хувилбарыг
суулгаад terminal-аа хааж дахин нээнэ үү.

## Ажиллуулах

### Хамгийн хялбар нь — давхар товших (Mac)

Төслийн хавтас дотор хоёр файл байна:

| Файл | Үйлдэл |
| --- | --- |
| **`start.command`** | Кодыг шинэчилж, сайтыг асаана, хөтөч нээнэ |
| **`stop.command`** | Серверийг зогсооно |

Finder дотроос давхар товшино. Хурдан хандахын тулд Dock руу чирж тавьж болно.

Сервер **арын дэвсгэрт** ажиллана: `start.command`-ийн Terminal цонхыг
хаасан ч, тэр цонхонд өөр тушаал бичсэн ч сайт унтрахгүй. Зогсоохын тулд
`stop.command` ажиллуулна.

Серверийн бүртгэл `.dev-server.log` файлд бичигдэнэ (git-д ордоггүй).

### Эсвэл гараар

Мөр бүрийг тусад нь, өмнөх нь дуустал хүлээж байгаад ажиллуулна:

```bash
git clone https://github.com/Barilgamn/lift.mn
cd lift.mn
npm install
npm run dev
```

Амжилттай бол ийм бичиг гарна:

```
  ➜  Local:   http://localhost:3000/
```

**Энэ бичиг гарсны дараа** хөтчөөрөө <http://localhost:3000> руу орно.

> Terminal цонхыг хаахгүй, `Ctrl+C` дарахгүй байх хэрэгтэй. Хаасан даруйд
> унтарч, хөтөч дээр `ERR_CONNECTION_REFUSED` гарна.

Нээлттэй хуудсууд (нүүр, DELTA LIFT, сэлбэг, засвар) Supabase-гүйгээр ажиллана.
Удирдлагын хэсэг (`/admin`) ажиллахын тулд доорх тохиргоог хийнэ.

## Supabase тохируулах

Өгөгдлийн сан, нэвтрэлтийг [Supabase](https://supabase.com) хариуцна. Дөрвөн алхам:

### 1. Төсөл үүсгэх

<https://supabase.com/dashboard> руу орж **New project** дарна. Бүс нутгийг
Сингапур (`ap-southeast-1`) сонговол Монголоос хамгийн хурдан. Өгөгдлийн сангийн
нууц үгийг хадгалж авна.

### 2. Түлхүүрүүдээ `.env` файлд бичих

Төсөл дотроо **Project Settings → API Keys** руу орж
**Publishable and secret API keys** табыг сонгоно. Дараа нь:

```bash
cp .env.example .env
```

`.env` файлаа нээж гурван утгыг солино:

| Хувьсагч | Хаанаас | Хэлбэр | Нууц эсэх |
| --- | --- | --- | --- |
| `VITE_SUPABASE_URL` | Дээд талын **Connect** товч, эсвэл Settings → Data API | `https://xxx.supabase.co` | Үгүй — хөтөч рүү явна |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | API Keys → Publishable key → `default` | `sb_publishable_...` | Үгүй — хөтөч рүү явна |
| `SUPABASE_SECRET_KEY` | API Keys → Secret keys → `default` | `sb_secret_...` | **Тийм** |

Secret түлхүүр дэлгэц дээр далдлагдсан байна — нүдний тэмдэг дарж харуулна.

> **Project URL олдохгүй бол** хөтчийнхөө хаягийг хараарай. Dashboard-ын хаяг
> `supabase.com/dashboard/project/АБВГД/...` хэлбэртэй байна. Тэр `АБВГД`
> хэсгийг аваад `https://АБВГД.supabase.co` болгоно — энэ л таны Project URL.
> Supabase цэсээ үе үе өөрчилдөг тул энэ арга хамгийн найдвартай.

> Secret түлхүүр өгөгдлийн сангийн **бүх хамгаалалтыг тойрдог**. Зөвхөн
> энэ компьютер дээрх терминалын скрипт ашиглана. Хэнд ч дамжуулж болохгүй,
> хөтчийн код дотор бүү бич, чат, имэйлээр бүү илгээ. `.env` файл git-д
> ордоггүй.

Publishable түлхүүр эсрэгээрээ — нийтэд ил байх зориулалттай, нуух шаардлагагүй
(Supabase өөрөө "can be safely shared publicly" гэж бичсэн байдаг). Түүнийг
хамгаалж буй зүйл бол доорх RLS бодлогууд.

<details>
<summary>Хуучин <code>anon</code> / <code>service_role</code> түлхүүр ашиглах бол</summary>

Supabase-ийн хуучин JWT түлхүүрүүд (`eyJ...`) **Legacy anon, service_role API
keys** таб дээр байна. Код нь хоёуланг нь дэмждэг — шинэ нэр олдохгүй бол
хуучныг ашиглана:

```bash
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
```

Шинэ төсөл дээр шинэ хэлбэрийг ашиглахыг зөвлөе.

</details>

### 3. Хүснэгтүүдийг үүсгэх

Supabase Dashboard дотроо **SQL Editor → New query** нээнэ. `supabase/schema.sql`
файлыг бүхэлд нь хуулж тавиад **Run** дарна. Дахин ажиллуулахад аюулгүй.

> Энэ алхмыг ч автоматаар хийлгэж болно — доорх 4-р алхмын доторх
> `SUPABASE_DB_URL` тайлбарыг үзнэ үү.

Энэ нь таван хүснэгт (`profiles`, `elevators`, `service_records`, `submissions`,
`products`), Row Level Security-ийн бодлогууд болон шинэ хэрэглэгчийг
автоматаар `viewer` (эрхгүй) болгодог trigger-ийг үүсгэнэ.

### 4. Өгөгдөл ачаалж, админ үүсгэх

`.env` бэлэн болсны дараа терминал дээрээ нэг тушаал:

```bash
npm run supabase:setup
```

Энэ нь гурван зүйлийг дараалан хийнэ: хүснэгт шалгах → эхлэлийн өгөгдөл
ачаалах → админ хэрэглэгч үүсгэх. Сүүлийн алхам дээр имэйл, нэр, нууц үгийг
асууна (нууц үг бичихэд дэлгэцэнд харагдахгүй). Асуулгагүйгээр:

```bash
npm run supabase:setup -- --email=та@lift.mn --name="Нэр" --password=...
```

Дахин ажиллуулахад аюулгүй — байгаа өгөгдлийг дарж бичихгүй.

Дараа нь `npm run dev` асааж <http://localhost:3000/admin> хаягаар нэвтэрнэ.

<details>
<summary>3-р алхмыг ч автоматаар хийлгэх бол</summary>

Dashboard → **Connect** товч дээр дарж холболтын мөрийг хуулна
(`postgresql://postgres.xxxx:...@...pooler.supabase.com:5432/postgres`).
`[YOUR-PASSWORD]` хэсгийг төсөл үүсгэхдээ өгсөн нууц үгээрээ солино. Дараа нь
`.env` файлдаа нэмнэ:

```bash
SUPABASE_DB_URL=postgresql://postgres.xxxx:НУУЦҮГ@...pooler.supabase.com:5432/postgres
```

Ингэвэл `npm run supabase:setup` нь `supabase/schema.sql`-ийг өөрөө ажиллуулна
— SQL Editor руу орох шаардлагагүй болно. Энэ мөр өгөгдлийн сангийн нууц үг
агуулдаг тул secret түлхүүртэй адил хамгаална.

</details>

<details>
<summary>Алхам тус бүрийг тусад нь ажиллуулах</summary>

```bash
npm run supabase:seed          # зөвхөн эхлэлийн өгөгдөл
npm run supabase:create-admin  # зөвхөн админ хэрэглэгч
```

`supabase:create-admin` нь аль хэдийн бүртгэлтэй имэйл дээр зөвхөн админ эрх
олгоно — шинэ хэрэглэгч үүсгэхгүй.

</details>

## Түгээмэл алдаа

**`npm: command not found`** — Node.js суугаагүй байна. Дээрх урьдчилсан шаардлагыг үзнэ үү.

**`bun: command not found`** — `bun` шаардлагагүй. `npm` ашиглана уу.

**`Port 3000 is in use`** — Тэр портыг өөр программ эзэлсэн байна. Өөр порт дээр асаана:

```bash
npm run dev -- --port=3001
```

**`ERR_CONNECTION_REFUSED`** — сервер ажиллаагүй байна. `start.command` дээр
давхар товшино. Асахгүй бол `.dev-server.log` файлын сүүлийн мөрүүдийг үзнэ үү.

**`Supabase тохируулагдаагүй байна`** — `.env` файл байхгүй эсвэл хөтчийн
түлхүүр дутуу. Аль мөр дутууг харахын тулд:

```bash
npm run supabase:check
```

Энэ нь нууц утгыг бүтнээр нь хэвлэхгүй — зөвхөн бөглөгдсөн эсэхийг харуулна.

Түгээмэл шалтгаан: терминалын скрипт ажиллаж байгаа ч (`SUPABASE_SECRET_KEY`
бөглөгдсөн) хөтчийн мөр (`VITE_SUPABASE_PUBLISHABLE_KEY`) жишээ утга хэвээр
үлдсэн байх. `.env`-ээ өөрчилсний дараа серверээ **дахин асаана** — Vite нь
тохиргоог зөвхөн асахдаа уншина.

**`Invalid API key`** — түлхүүр буруу табаас хуулагдсан байж магадгүй.
Хөтчид зориулсан нь `sb_publishable_...`-аар эхэлнэ, терминалын скриптийнх
`sb_secret_...`-аар. Хоёулаа ижил төсөл дээрх байх ёстой.

**`Энэ бүртгэлд админ эрх олгогдоогүй байна`** — хэрэглэгч бүртгэлтэй ч `viewer`
эрхтэй байна. `npm run supabase:create-admin` тушаалыг тэр имэйлээр
ажиллуулбал админ болгоно.

## Хуудаснууд

Сайт нь дараах хаягтай:

| Хаяг | Хуудас |
| --- | --- |
| `/` | Портал нүүр — гурван том цэс |
| `/delta-lift` | DELTA LIFT — компанийн танилцуулга |
| `/parts` | Сэлбэг хэрэгсэл |

Танихгүй хаяг портал руу буцаана.

Порталын гурван цэсний дараалал дэлгэцээс хамаарна: компьютер дээр
**Засвар → Сэлбэг → DELTA LIFT**, гар утсанд **Сэлбэг → Засвар →
DELTA LIFT**. DOM дараалал нь гар утсныхтай таарсан (Tab товчны дараалал
түүнийг дагадаг), дэлгэцийнхийг `md:order-*` -ээр эргүүлнэ.

### Удирдлагын хэсэг

`/admin` хаягаар нэвтэрнэ. Дотроо таван хэсэгтэй:

| Хэсэг | Агуулга |
| --- | --- |
| Хяналтын самбар | Шинэ хүсэлт, анхаарал шаардсан лифт, нөөцийн байдал |
| Бүртгэлүүд | Сайтаар ирсэн бүх маягтын хүсэлт, төлөв өөрчлөх |
| Газрын зураг | Үйлчилгээнд буй лифтүүдийн байршил, төлөвөөр өнгөөр ялгасан |
| Лифтүүд | Тоноглол бүрийн үзүүлэлт, төлөв, засварын түүх, шинэ бүртгэл нэмэх |
| Бүтээгдэхүүн | Сэлбэгийн нэр, зураг, үнэ, нөөцийн үлдэгдэл засах |

Газрын зураг нь OpenStreetMap-ын дэвсгэр татдаг тул интернэт холболт шаардана.
Лифтүүдийн байршлын координат, засварын түүх нь эхлэлийн жишээ өгөгдөл — бодит
бүртгэлээр солино.

## Өгөгдлийн сан ба эрх

| | |
| --- | --- |
| Өгөгдлийн сан | Supabase (Postgres) |
| Нэвтрэлт | Supabase Auth — имэйл, нууц үг |
| Эрх | Postgres Row Level Security (`supabase/schema.sql`) |

### Эрх хэрхэн ажилладаг

Хамгаалалт нь **хөтчийн код дээр биш, өгөгдлийн сан дээр** байна. Хөтчийн код
хэн ч уншиж, өөрчилж болно гэж үзээд бодлогуудыг серверт бичсэн:

- Хүснэгт бүрт **Row Level Security асаалттай**. Бодлого зөвшөөрөөгүй бол ямар ч
  мөр уншигдахгүй, бичигдэхгүй.
- Шинээр бүртгүүлсэн хэрэглэгч `handle_new_user()` trigger-ээр автоматаар
  **`viewer`** үүрэгтэй болно — ямар ч өгөгдөл харахгүй. Хэн нэгэн санамсаргүй
  бүртгүүлсэн ч дотогш орохгүй.
- `profiles` хүснэгт дээр **UPDATE бодлого байхгүй** тул хэрэглэгч өөрөө өөрийгөө
  админ болгож чадахгүй. Үүргийг зөвхөн SQL Editor эсвэл secret түлхүүрээр л
  өөрчилнө.
- `is_admin()` функц нь `security definer` — админ эсэхийг шалгахдаа өөрөө
  `profiles`-ыг тойрч уншдаг тул бодлогууд хооронд нь хаалт үүсгэхгүй.
- **Маягтын хүсэлт**: нэвтрээгүй зочин зөвхөн **нэмнэ**, уншиж чадахгүй.
  Ингэснээр бусдын илгээсэн хүсэлт, утасны дугаар гадагш гарахгүй. Уртын
  хязгаар, `status = 'new'` шалгалтыг ч бодлого дотор хийнэ.
- **Бүтээгдэхүүн**: дэлгүүр нийтэд нээлттэй тул хэн ч уншина, зөвхөн админ засна.
- **Publishable** түлхүүр нийтэд ил байх зориулалттай — түүнийг нуух
  шаардлагагүй. Өгөгдлийг хамгаалж буй зүйл бол RLS.

### Хүснэгтүүд

| Хүснэгт | Агуулга | Унших | Бичих |
| --- | --- | --- | --- |
| `profiles` | Хэрэглэгчийн нэр, үүрэг | Өөрийн мөр | — |
| `elevators` | Лифт бүрийн үзүүлэлт, байршил, төлөв | Админ | Админ |
| `service_records` | Засвар үйлчилгээний түүх | Админ | Админ |
| `submissions` | Сайтаар ирсэн маягтын хүсэлт | Админ | Хэн ч нэмнэ |
| `products` | Сэлбэгийн нэр, үнэ, нөөц | Хэн ч | Админ |

`service_records` дээр шинэ мөр нэмэгдэхэд trigger нь холбогдох лифтний
`last_service_at` талбарыг шинэчилнэ.

### Нөөцлөлт

Supabase Dashboard дотроо **Database → Backups** хэсэгт өдөр тутмын нөөцлөлт
байна. Гараар татах бол **Database → Connection string** дээрх мэдээллээр
`pg_dump` ажиллуулна.

### Байршуулах

```bash
npm install
npm run build
```

`dist/` фолдерыг Netlify, Cloudflare Pages, Vercel гэх мэт статик хостинг руу
байршуулна. Угсрах үед `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` хоёр
хувьсагч орчинд байх ёстой — хостингийнхоо тохиргоонд нэмнэ.
`SUPABASE_SECRET_KEY`-г хостинг дээр **бүү** нэм.

> **Хостинг дээр анхаарах:** энэ бол нэг хуудаст програм (SPA). Хэрэглэгч
> `lift.mn/admin` руу шууд орох үед сервер `index.html`-ийг буцаах ёстой.
> Эс бөгөөс 404 гарна. Хост тус бүр өөр файл уншдаг:
>
> | Хост | Файл |
> | --- | --- |
> | Vercel | `vercel.json` |
> | Netlify, Cloudflare Pages | `public/_redirects` |
> | Nginx | `try_files $uri /index.html;` мөр |
>
> Эхний хоёр файл нь энэ төсөлд байгаа.

### Vercel дээр

Тохиргоо нь `vercel.json`-д бэлэн. Гэхдээ орчны хувьсагчийг **Vercel дээр
тусад нь** бөглөнө — `.env` файл git-д ордоггүй тул хамт очихгүй:

Project → Settings → Environment Variables дотор хоёр утга нэмнэ:

```
VITE_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY
```

`SUPABASE_SECRET_KEY`-г Vercel дээр **бүү нэм** — тэр нь зөвхөн таны
компьютер дээрх терминалын скриптэд хэрэгтэй.

> Vite нь орчны хувьсагчийг **угсрах үедээ** кодод шингээдэг. Тиймээс
> хувьсагч нэмсний дараа заавал **Redeploy** хийнэ — эс бөгөөс хуучин
> хувилбар нь хувьсагчгүйгээр угсарсан хэвээр үлдэж, `/admin` дээр
> "Supabase тохируулагдаагүй" гэж харуулсаар байна.

## Нүүр тал ↔ админы холбоо

| Сайтан дээр | Хаана очдог | Админ дээр |
| --- | --- | --- |
| Засварын хүсэлт | `submissions` (`SRV-`) | Бүртгэлүүд |
| Яаралтай дуудлага | `submissions` (`SOS-`) | Бүртгэлүүд |
| Цаг захиалга | `submissions` (`BKG-`) | Бүртгэлүүд |
| Үнийн санал | `submissions` (`QTE-`) | Бүртгэлүүд |
| Сэлбэг захиалах | `submissions` (`SRC-`) + зураг | Бүртгэлүүд |
| Сагсны захиалга | `submissions` (`ORD-`) + зураг | Бүртгэлүүд |
| Сэлбэгийн дэлгүүр | `products`-оос уншина | Бүтээгдэхүүн |

Дэлгүүрийн бүх бараа `src/data/catalogData.ts`-ээс ирнэ. Өмнө нь энд
байсан 8 жишээ бараа (Unsplash зурагтай) хасагдсан — каталог бодит болсон
тул тэдгээр нь зөрчил үүсгэж байв.

Маягт бүр `src/lib/submitForm.ts`-ээр дамжина. Илгээлт бүтэлгүйтвэл
амжилтын дэлгэц **харуулахгүй** — алдаа болон залгах дугаарыг харуулна.

### Зураг хавсаргах

Сэлбэг захиалах болон сагсны захиалгад хэрэглэгч **3 хүртэл зураг**
хавсаргана. Зургийг хөтөч дээр шахна (`src/lib/photoAttach.ts`): урт талыг
1280 пиксел болгож, JPEG чанарыг хэмжээнд багтах хүртэл буурааж, 400 КБ-аас
доош болгоно. Утасны 4000 пикселийн зураг ихэвчлэн 50-150 КБ болдог.

Зураг нь `submissions.details` дотор `Зураг 1`, `Зураг 2` ... гэсэн
түлхүүрээр data URL хэлбэрээр орно — тусдаа сан (Supabase Storage)
шаардахгүй. Админы дэлгэц `data:image/` угтварыг таниж, текст талбаруудаас
салгаж зураг болгон харуулна.

RLS бодлого `details`-ийн хэмжээг 2.5 сая тэмдэгтээр хязгаарлана. Энэ
хязгааргүй бол нэвтрээгүй хэн ч дурын хэмжээний өгөгдөл бичих боломжтой.

### Бүтээгдэхүүн ба загварууд

Нэг бүтээгдэхүүн дотор олон загвар (variant) багтана. Жишээ нь **Лифтний
товч** гэсэн нэг бүтээгдэхүүн дотор брэнд тус бүрийн 21 загвар
(BR27C/A311, KDS50/300, MTD270 ...) байна. Загвар бүр өөрийн код, тайлбар,
брэнд, **үнэ, нөөц, зурагтай** — бүгдийг админ дээрээс тусад нь засна.

Сайт дээр: карт дээр загварын тоо, үнийн хязгаар харагдана → "Загвар
сонгох" дарахад дэлгэрэнгүй цонх нээгдэнэ. Сагсанд `бүтээгдэхүүн::загвар`
гэсэн дугаараар орох тул загвар бүр тусдаа тоологдоно.

Дэлгүүрийн карт дээр **зураг, нэр, "Үзүүлэлт"** гурвуулаа дэлгэрэнгүй хуудас
руу хөтөлнө. "Сагслах" / "Загвар сонгох" товч л өөр үйлдэл хийнэ. Зургийн
холбоос нь `tabIndex={-1}` — нэртэй ижил газар очдог тул гараар навигацлахад
давхар зогсолт үүсгэхгүй.

### Дэлгэрэнгүй хуудас

`src/components/ProductPage.tsx`, хаяг нь `/parts/:id`. Popup биш бүтэн
хуудас тул хаягийг хуваалцах, хөтчийн буцах товч ашиглах, хайлтын систем
индекслэх боломжтой. Байршлын мөрөнд барааны нэр нэмэгдэнэ.

Дээд талд зураг зүүн, үзүүлэлт баруун талд; доор нь загварууд сүлжээгээр
(дэлгэц дээр 3 багана); хамгийн доор **санал болгох бүтээгдэхүүн** — ижил
ангиллаас эхлээд дөрөв.

Барааны болон загварын зураг дээр дарвал бүтэн дэлгэцээр томорно
(`ImageZoom.tsx`), `Esc` -ээр хаана.

> Каталогийн зураг PDF дотроо ~250 пиксел байсан тул томруулахад зөөлөрч
> харагдана. Админаас оруулсан зураг 1280 пиксел тул хурц гарна.

Үнийг 0 орхивол "Үнэ тохиролцоно" гэж харагдана. Каталогоос ачаалсан
загварууд бүгд 0 үнэтэй — админ дээрээс үнэ тавина.

Өгөгдөл нь `src/data/catalogData.ts` файлд (HUSHENG каталог, 26
бүтээгдэхүүн, 511 загвар). Зургууд `public/images/parts/` дотор. Тэр файлыг
гараар бүү зас — `npm run supabase:seed` үүнээс ачаална.

`seed` нь хүснэгт хоосон үед л ачаалдаг. Каталог шинэчлэгдсэн эсвэл хуучин
өгөгдөл дээр дарж ачаалах бол:

```bash
npm run supabase:seed -- --replace-products
```

Энэ нь зөвхөн `products` хүснэгтийг цэвэрлэнэ — лифт, засварын түүх,
маягтын хүсэлт хөндөгдөхгүй.

Дэлгүүр нь `products` хүснэгтээс уншина. Хүснэгт хоосон бол дэлгүүр хоосон
харагдана. `.env` бөглөгдөөгүй эсвэл уншилт алдаа өгсөн үед л кодод суусан
каталог руу шилжинэ — тэр үед үнэ нь "тохиролцоно" гэж харагдана, учир нь
админы тавьсан үнэ зөвхөн өгөгдлийн санд байдаг.

### Дэлгүүрийн байрлал

`lg` (1024px) -ээс дээш өргөнд ангилал **зүүн талд босоо самбар** болж,
барааны тоог хажууд нь харуулна. Түүнээс бага дэлгэцэд хөндлөн гүйдэг
мөр болно. Самбар гүйлгэхэд дагаж наалддаг (`lg:sticky`).

Баруун талд: хайлт ба брэндийн шүүлтүүр → **хоёр мөр бараа** → **тусгай
захиалгын маягт** бүтэн өргөнөөр → үлдсэн бараа. Хоёр мөр гэдэг нь
өргөнөөс хамаарна: гар утсанд 2, таблетад 4, компьютерт 6 бараа
(`PartsView.tsx` доторх `columnsAt`).

Хуудасны өмнөх том толгой хэсэг (гарчиг, сагсны карт, давуу талууд)
хасагдсан — сагсанд навбарын дээд талын товчоор ордог.

## Одоогийн төлөв

Удирдлагын хэсэг нь Supabase дээр бүрэн ажиллана. Дараах зүйлс хараахан
хийгдээгүй:

- **Хүсэлтийн явцыг** зөвхөн илгээсэн төхөөрөмж дээрээ хардаг. Зочинд
  `submissions`-ыг унших эрх өгдөггүй (бусдын утасны дугаар хамгаалагдана)
  тул өөр утас, компьютерээс дугаараар хайх боломжгүй. Бүх төхөөрөмжөөс
  харуулах бол `security definer` функц (дугаар + утас хоёуланг таарсан үед
  л төлөв буцаадаг) нэмэх хэрэгтэй.
- **Сагсны агуулга** хөтчийн `localStorage`-д хадгалагдана.
- **Эрхийн ялгаа** хоёрхон — `admin` бүгдийг харж, засна; `viewer` юу ч харахгүй.
  Инженер, менежер гэх мэт үүрэг хуваах шаардлагатай бол `profiles.role` дээр
  нэмж, бодлогуудыг өргөтгөнө.
- **Нууц үг сэргээх** урсгал сайт дээр байхгүй. Supabase Dashboard →
  Authentication → Users хэсгээс солино.
- **Бүтээгдэхүүний зураг** одоогоор линк, файлын зам эсвэл base64-ээр
  хадгалагдана. Supabase Storage руу шилжүүлэх нь дараагийн алхам.
- **Каталогийн загваруудын зураг** PDF-ээс автоматаар гаргаж, дараалалаар нь
  тааруулсан. 26 ангиллын 23-д нь зургийн тоо загварын тоотой яг таарсан тул
  холболт зөв. Үлдсэн гурав (ган бүс, татлага, бариулын бүс) нь хэмжээгээр
  ялгардаг тул зөвхөн нэг нүүр зурагтай. Буруу таарсан зураг тааралдвал
  админ дээрээс дарж солино.
- Брэнд, төслийн зарим зураг Unsplash-аас гадны линкээр ачаалагдана.
