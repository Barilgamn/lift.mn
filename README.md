# LIFT.MN

Монголын лифт, эскалаторын нэгдсэн цахим портал. DELTA LIFT брэндийн танилцуулга,
засвар үйлчилгээний захиалга, сэлбэг хэрэгслийн цахим худалдааг нэг дор нэгтгэсэн.

## Урьдчилсан шаардлага

**Node.js 20 буюу түүнээс дээш хувилбар.** Өөр юу ч суулгах шаардлагагүй.

Суусан эсэхээ шалгах:

```bash
node -v
```

Хэрэв `command not found` гарвал [nodejs.org](https://nodejs.org) дээрээс **LTS** хувилбарыг
суулгаад terminal-аа хааж дахин нээнэ үү.

## Ажиллуулах

Мөр бүрийг тусад нь, өмнөх нь дуустал хүлээж байгаад ажиллуулна:

```bash
git clone https://github.com/Barilgamn/lift.mn
cd lift.mn
npm install
npm run dev
```

Амжилттай бол ийм бичиг гарна:

```
  ➜  Local:   http://localhost:3000/
```

**Энэ бичиг гарсны дараа** хөтчөөрөө <http://localhost:3000> руу орно.

> Terminal цонхыг хаахгүй, `Ctrl+C` дарахгүй байх хэрэгтэй. Хаасан даруйд
> унтарч, хөтөч дээр `ERR_CONNECTION_REFUSED` гарна.

Нээлттэй хуудсууд (нүүр, DELTA LIFT, сэлбэг, засвар) Supabase-гүйгээр ажиллана.
Удирдлагын хэсэг (`/admin`) ажиллахын тулд доорх тохиргоог хийнэ.

## Supabase тохируулах

Өгөгдлийн сан, нэвтрэлтийг [Supabase](https://supabase.com) хариуцна. Дөрвөн алхам:

### 1. Төсөл үүсгэх

<https://supabase.com/dashboard> руу орж **New project** дарна. Бүс нутгийг
Сингапур (`ap-southeast-1`) сонговол Монголоос хамгийн хурдан. Өгөгдлийн сангийн
нууц үгийг хадгалж авна.

### 2. Түлхүүрүүдээ `.env` файлд бичих

Төсөл дотроо **Project Settings → API Keys** руу орж
**Publishable and secret API keys** табыг сонгоно. Дараа нь:

```bash
cp .env.example .env
```

`.env` файлаа нээж гурван утгыг солино:

| Хувьсагч | Хаанаас | Хэлбэр | Нууц эсэх |
| --- | --- | --- | --- |
| `VITE_SUPABASE_URL` | Project Settings → API → Project URL | `https://xxx.supabase.co` | Үгүй — хөтөч рүү явна |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | API Keys → Publishable key → `default` | `sb_publishable_...` | Үгүй — хөтөч рүү явна |
| `SUPABASE_SECRET_KEY` | API Keys → Secret keys → `default` | `sb_secret_...` | **Тийм** |

Secret түлхүүр дэлгэц дээр далдлагдсан байна — нүдний тэмдэг дарж харуулна.

> Secret түлхүүр өгөгдлийн сангийн **бүх хамгаалалтыг тойрдог**. Зөвхөн
> энэ компьютер дээрх терминалын скрипт ашиглана. Хэнд ч дамжуулж болохгүй,
> хөтчийн код дотор бүү бич, чат, имэйлээр бүү илгээ. `.env` файл git-д
> ордоггүй.

Publishable түлхүүр эсрэгээрээ — нийтэд ил байх зориулалттай, нуух шаардлагагүй
(Supabase өөрөө "can be safely shared publicly" гэж бичсэн байдаг). Түүнийг
хамгаалж буй зүйл бол доорх RLS бодлогууд.

<details>
<summary>Хуучин <code>anon</code> / <code>service_role</code> түлхүүр ашиглах бол</summary>

Supabase-ийн хуучин JWT түлхүүрүүд (`eyJ...`) **Legacy anon, service_role API
keys** таб дээр байна. Код нь хоёуланг нь дэмждэг — шинэ нэр олдохгүй бол
хуучныг ашиглана:

```bash
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
```

Шинэ төсөл дээр шинэ хэлбэрийг ашиглахыг зөвлөе.

</details>

### 3. Хүснэгтүүдийг үүсгэх

Supabase Dashboard дотроо **SQL Editor → New query** нээнэ. `supabase/schema.sql`
файлыг бүхэлд нь хуулж тавиад **Run** дарна. Дахин ажиллуулахад аюулгүй.

> Энэ алхмыг ч автоматаар хийлгэж болно — доорх 4-р алхмын доторх
> `SUPABASE_DB_URL` тайлбарыг үзнэ үү.

Энэ нь таван хүснэгт (`profiles`, `elevators`, `service_records`, `submissions`,
`products`), Row Level Security-ийн бодлогууд болон шинэ хэрэглэгчийг
автоматаар `viewer` (эрхгүй) болгодог trigger-ийг үүсгэнэ.

### 4. Өгөгдөл ачаалж, админ үүсгэх

`.env` бэлэн болсны дараа терминал дээрээ нэг тушаал:

```bash
npm run supabase:setup
```

Энэ нь гурван зүйлийг дараалан хийнэ: хүснэгт шалгах → эхлэлийн өгөгдөл
ачаалах → админ хэрэглэгч үүсгэх. Сүүлийн алхам дээр имэйл, нэр, нууц үгийг
асууна (нууц үг бичихэд дэлгэцэнд харагдахгүй). Асуулгагүйгээр:

```bash
npm run supabase:setup -- --email=та@lift.mn --name="Нэр" --password=...
```

Дахин ажиллуулахад аюулгүй — байгаа өгөгдлийг дарж бичихгүй.

Дараа нь `npm run dev` асааж <http://localhost:3000/admin> хаягаар нэвтэрнэ.

<details>
<summary>3-р алхмыг ч автоматаар хийлгэх бол</summary>

Dashboard → **Connect** товч дээр дарж холболтын мөрийг хуулна
(`postgresql://postgres.xxxx:...@...pooler.supabase.com:5432/postgres`).
`[YOUR-PASSWORD]` хэсгийг төсөл үүсгэхдээ өгсөн нууц үгээрээ солино. Дараа нь
`.env` файлдаа нэмнэ:

```bash
SUPABASE_DB_URL=postgresql://postgres.xxxx:НУУЦҮГ@...pooler.supabase.com:5432/postgres
```

Ингэвэл `npm run supabase:setup` нь `supabase/schema.sql`-ийг өөрөө ажиллуулна
— SQL Editor руу орох шаардлагагүй болно. Энэ мөр өгөгдлийн сангийн нууц үг
агуулдаг тул secret түлхүүртэй адил хамгаална.

</details>

<details>
<summary>Алхам тус бүрийг тусад нь ажиллуулах</summary>

```bash
npm run supabase:seed          # зөвхөн эхлэлийн өгөгдөл
npm run supabase:create-admin  # зөвхөн админ хэрэглэгч
```

`supabase:create-admin` нь аль хэдийн бүртгэлтэй имэйл дээр зөвхөн админ эрх
олгоно — шинэ хэрэглэгч үүсгэхгүй.

</details>

## Түгээмэл алдаа

**`npm: command not found`** — Node.js суугаагүй байна. Дээрх урьдчилсан шаардлагыг үзнэ үү.

**`bun: command not found`** — `bun` шаардлагагүй. `npm` ашиглана уу.

**`Port 3000 is in use`** — Тэр портыг өөр программ эзэлсэн байна. Өөр порт дээр асаана:

```bash
npm run dev -- --port=3001
```

**`ERR_CONNECTION_REFUSED`** — `npm run dev` ажиллаагүй эсвэл зогссон байна.
Terminal дээрээ `VITE ready` бичиг байгаа эсэхийг шалгана уу.

**`Supabase тохируулагдаагүй байна`** — `.env` файл байхгүй эсвэл түлхүүр
буруу. Дээрх 2-р алхмыг үзнэ үү. `.env` файлыг өөрчилсний дараа `npm run dev`-ээ
дахин асаана — Vite нь тохиргоог зөвхөн асахдаа уншина.

**`Invalid API key`** — түлхүүр буруу табаас хуулагдсан байж магадгүй.
Хөтчид зориулсан нь `sb_publishable_...`-аар эхэлнэ, терминалын скриптийнх
`sb_secret_...`-аар. Хоёулаа ижил төсөл дээрх байх ёстой.

**`Энэ бүртгэлд админ эрх олгогдоогүй байна`** — хэрэглэгч бүртгэлтэй ч `viewer`
эрхтэй байна. `npm run supabase:create-admin` тушаалыг тэр имэйлээр
ажиллуулбал админ болгоно.

| Хэсэг | Агуулга |
| --- | --- |
| Хяналтын самбар | Шинэ хүсэлт, анхаарал шаардсан лифт, нөөцийн байдал |
| Бүртгэлүүд | Сайтаар ирсэн бүх маягтын хүсэлт, төлөв өөрчлөх |
| Газрын зураг | Үйлчилгээнд буй лифтүүдийн байршил, төлөвөөр өнгөөр ялгасан |
| Лифтүүд | Тоноглол бүрийн үзүүлэлт, төлөв, засварын түүх, шинэ бүртгэл нэмэх |

## Өгөгдлийн сан ба эрх

| | |
| --- | --- |
| Өгөгдлийн сан | Supabase (Postgres) |
| Нэвтрэлт | Supabase Auth — имэйл, нууц үг |
| Эрх | Postgres Row Level Security (`supabase/schema.sql`) |

### Эрх хэрхэн ажилладаг

Хамгаалалт нь **хөтчийн код дээр биш, өгөгдлийн сан дээр** байна. Хөтчийн код
хэн ч уншиж, өөрчилж болно гэж үзээд бодлогуудыг серверт бичсэн:

- Хүснэгт бүрт **Row Level Security асаалттай**. Бодлого зөвшөөрөөгүй бол ямар ч
  мөр уншигдахгүй, бичигдэхгүй.
- Шинээр бүртгүүлсэн хэрэглэгч `handle_new_user()` trigger-ээр автоматаар
  **`viewer`** үүрэгтэй болно — ямар ч өгөгдөл харахгүй. Хэн нэгэн санамсаргүй
  бүртгүүлсэн ч дотогш орохгүй.
- `profiles` хүснэгт дээр **UPDATE бодлого байхгүй** тул хэрэглэгч өөрөө өөрийгөө
  админ болгож чадахгүй. Үүргийг зөвхөн SQL Editor эсвэл secret түлхүүрээр л
  өөрчилнө.
- `is_admin()` функц нь `security definer` — админ эсэхийг шалгахдаа өөрөө
  `profiles`-ыг тойрч уншдаг тул бодлогууд хооронд нь хаалт үүсгэхгүй.
- **Маягтын хүсэлт**: нэвтрээгүй зочин зөвхөн **нэмнэ**, уншиж чадахгүй.
  Ингэснээр бусдын илгээсэн хүсэлт, утасны дугаар гадагш гарахгүй. Уртын
  хязгаар, `status = 'new'` шалгалтыг ч бодлого дотор хийнэ.
- **Бүтээгдэхүүн**: дэлгүүр нийтэд нээлттэй тул хэн ч уншина, зөвхөн админ засна.
- **Publishable** түлхүүр нийтэд ил байх зориулалттай — түүнийг нуух
  шаардлагагүй. Өгөгдлийг хамгаалж буй зүйл бол RLS.

### Хүснэгтүүд

| Хүснэгт | Агуулга | Унших | Бичих |
| --- | --- | --- | --- |
| `profiles` | Хэрэглэгчийн нэр, үүрэг | Өөрийн мөр | — |
| `elevators` | Лифт бүрийн үзүүлэлт, байршил, төлөв | Админ | Админ |
| `service_records` | Засвар үйлчилгээний түүх | Админ | Админ |
| `submissions` | Сайтаар ирсэн маягтын хүсэлт | Админ | Хэн ч нэмнэ |
| `products` | Сэлбэгийн нэр, үнэ, нөөц | Хэн ч | Админ |

`service_records` дээр шинэ мөр нэмэгдэхэд trigger нь холбогдох лифтний
`last_service_at` талбарыг шинэчилнэ.

### Нөөцлөлт

Supabase Dashboard дотроо **Database → Backups** хэсэгт өдөр тутмын нөөцлөлт
байна. Гараар татах бол **Database → Connection string** дээрх мэдээллээр
`pg_dump` ажиллуулна.

### Байршуулах

```bash
npm install
npm run build
```

`dist/` фолдерыг Netlify, Cloudflare Pages, Vercel гэх мэт статик хостинг руу
байршуулна. Угсрах үед `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` хоёр
хувьсагч орчинд байх ёстой — хостингийнхоо тохиргоонд нэмнэ.
`SUPABASE_SECRET_KEY`-г хостинг дээр **бүү** нэм.

> **Хостинг дээр анхаарах:** энэ бол нэг хуудаст програм (SPA). Хэрэглэгч
> `lift.mn/delta-lift` руу шууд орох үед сервер `index.html`-ийг буцаах ёстой.
> Netlify, Cloudflare Pages дээр `public/_redirects` файл үүнийг хийнэ. Nginx
> дээр бол `try_files $uri /index.html;` мөр нэмнэ. Эс бөгөөс шууд хаягаар
> орох үед 404 гарна.

## Одоогийн төлөв

Удирдлагын хэсэг нь Supabase дээр бүрэн ажиллана. Дараах зүйлс хараахан
хийгдээгүй:

- **Сайтын маягтууд** (засварын хүсэлт, үнийн санал, захиалга) хараахан
  `submissions` хүснэгт рүү илгээгдээгүй — одоогоор зөвхөн дэлгэц дээр
  амжилтын мэдэгдэл харуулна. Хүснэгт, бодлого нь бэлэн байгаа тул холбоход л
  үлдсэн.
- **Сагсны агуулга** хөтчийн `localStorage`-д хадгалагдана.
- **Эрхийн ялгаа** хоёрхон — `admin` бүгдийг харж, засна; `viewer` юу ч харахгүй.
  Инженер, менежер гэх мэт үүрэг хуваах шаардлагатай бол `profiles.role` дээр
  нэмж, бодлогуудыг өргөтгөнө.
- **Нууц үг сэргээх** урсгал сайт дээр байхгүй. Supabase Dashboard →
  Authentication → Users хэсгээс солино.
- **Бүтээгдэхүүний зураг** одоогоор линк эсвэл base64-ээр хадгалагдана.
  Supabase Storage руу шилжүүлэх нь дараагийн алхам.
